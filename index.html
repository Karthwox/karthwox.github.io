I’m a Computer Science student at IIIT Bangalore. I’m interested in how AI agents behave once they’re doing real work: where they fail, how to measure it, and what makes them dependable enough to trust.

My work splits two ways. Research: careful, small-scale experiments on LLMs and coding agents, written up as papers when the results hold up. Engineering: tools, agent skills and open-source contributions that make agents more reliable to build with.

I test most ideas with a quick pilot before committing to them, and I write up the results either way in pilot notes: what I tested, what I found, and why I kept going or stopped.

Outside of this, I’m an elected member of the college’s Student Affairs Council, play bass in a six-piece cover band, help run Symphony (the college music club), and play table tennis and basketball.

    Does a Security Skill Beat a One-Line Reminder? A Blinded, Pre-Registered Test of Agent Skill Files for Safer AI-Generated Code
    Karthik Annadurai
    Nov 2026
    Abs DOI Bib Supp Code

    AI coding agents often build working apps while leaving out security protections nobody asked for. This study tests a security skill file for Codex CLI against a one-line security reminder, no guidance, and a public security skill, using pre-registered decision rules, blinded code review and a feature-fidelity check. On a stronger model, the reminder alone removed every critical failure on the original prompts. On a weaker model, the skill was not detectably better than the reminder on fresh prompt variants or on ten probes mapped to the OWASP Top 10. A final 400-run phase added a security checklist and a length-matched placebo: the reminder, checklist and skill each cut critical failures substantially while the placebo did not, and the skill showed no detectable advantage over the reminder (+5 points in failure rate, 95% interval -9 to +19) at 1.7 times the tokens of no guidance. Security content, not instruction length, appears to carry most of the benefit.
